# ln-vox for ComfyUI

ComfyUI nodes that drive the ln-vox pipeline as a graph: every stage of
`scripts/run_pipeline.sh` is a node, plus nodes to inspect artifacts,
hand-cast voices and audition audio.

```bash
ln -s "$PWD/comfyui" /path/to/ComfyUI/custom_nodes/comfyui-lnvox   # from the ln-vox repo root
# restart ComfyUI → nodes under "ln-vox/", workflows under Templates → comfyui-lnvox
```

The full guide — how nodes chain and cache, every node's inputs, the example
workflows, troubleshooting — is in the docs site: `docs/src/content/docs/guides/comfyui.md`
(`cd docs && npm run dev`, then *Guides → ComfyUI nodes*).

## Layout

| File | What |
| --- | --- |
| `__init__.py` | Registers the nodes and the `web/` extension |
| `nodes.py` | The node classes — one per stage, plus Inspect / Load Audio / Set Voice / Run Pipeline |
| `runtime.py` | Subprocess runner (live logs, Cancel), retries, LLM server lifecycle, venv phase swaps |
| `inspect_views.py` | Text views over a book's artifacts (stdlib `json` only) |
| `audio.py` | Windowed ffmpeg decode into ComfyUI `AUDIO` |
| `web/lnvox.js` | Log panel on every ln-vox node |
| `example_workflows/` | Generated by `tools/build_workflows.py` — don't hand-edit |

Nothing here imports `lnvox`: every stage runs as `uv run lnvox …` inside the
checkout, and the venv is swapped between the LLM and TTS phases with
`scripts/run_pipeline.sh --prepare-env llm|tts|vibevoice`, exactly as the
launcher does. ComfyUI's own environment is never modified.

## Development

```bash
python3 comfyui/tools/build_workflows.py      # after changing any node's inputs
python3 tests/test_comfyui_pack.py            # no ComfyUI or torch needed
```
