```text
LLM phase — Gemma 4 on llama.cpp · vLLM · mlx
  EPUB / .txt ─► ingest ─► s1 cast ─► s2 scenes ─► voice cast ─► audit ─► s3 director
                                                                               │
TTS phase — Dramabox · VibeVoice, then ffmpeg                                  ▼
  .m4b ◄── s5 mix ◄── s4 TTS ◄──────────────────────────────────────── directed beats
    └──► s6 sync ──► synced EPUB + sync_manifest.json
```

<CardGrid>
	<Card title="Three modes" icon="open-book">
		**Narration** for novels (multi-voice, acted), **lecture** for non-fiction (one steady
		voice, verbatim, code and tables shown as images) and **scenario** for plays (verbatim
		lines, per-line emotion, a timed sync file).
	</Card>
	<Card title="Two GPU phases, one launcher" icon="rocket">
		`scripts/run_pipeline.sh` starts the LLM server, runs every LLM stage, hands the GPU to
		the TTS model, then mixes and syncs — swapping the venv between the incompatible
		torch builds each phase needs.
	</Card>
	<Card title="Idempotent, cached stages" icon="setting">
		Every stage is its own `lnvox` command writing JSON under `artifacts/<book>/`. Re-running
		resumes; the TTS cache is content-addressed, so editing one line re-renders one beat.
	</Card>
	<Card title="Series-aware" icon="list-format">
		Volumes of a series share voices: recurring characters and the narrator keep their
		clips from volume to volume automatically.
	</Card>
</CardGrid>
